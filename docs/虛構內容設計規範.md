# 虛構人物與事件設計規範

> 目標：真實選舉與歷史事件只供規則設計、數值範圍及制度理解參考；玩家可見內容一律採虛構人物、團體、事件、情節與選舉結果，不將真實人物或單一事件改名後直接搬入遊戲。

## 設計原則

1. **來源資料與遊戲內容分離：**真實票數、法規、研究與史料留在開發者使用的參考／校準層；遊戲劇情、事件包、候選人和政黨／團體名稱、人物卡、`--history`、命令列回饋、戰績檔與發行說明都必須改用虛構內容，不輸出可識別的真實人物、政黨、組織、事件或選舉結果。
2. **參考機制，不重演個案：**可抽取議題熱度、組織動員、反動員、程序門檻、媒體信任、政策責任、投票參與等抽象機制；不得以單一真人或真實事件作一對一原型，亦不把來源個案的爭議直接轉成固定陣營加減分。
3. **多源合成、改變因果鏈：**每個故事情節至少綜合多種不同背景的制度／社會素材；改寫時間、地點、機構、角色關係、事件順序、訴求與後果。若熟悉臺灣政治的玩家仍能直接辨認唯一真實對象，就繼續改寫或刪除。
4. **虛構角色具持續性：**人物以虛構身分、職務、價值取捨、關係網與記憶旗標組成；後續場景需回應玩家先前的承諾、拒答、查證及組織選擇，不把真人言行或未證實動機當作角色設定。
5. **可驗證但不冒充預測：**遊戲內支持度、施政評價、議題評價、簽名數與投票結果均標示為本局情境模型；歷史結果只用於測試門檻和極端結果範圍，不宣稱能重現真實投票者或因果。
6. **制度規則可真實、人物故事須虛構：**涉及罷免門檻、程序期間等制度時可採公開法規並標明依據；法規正確不代表可以把某個真實罷免案作成玩家可操作的原樣重演。

## 事件與人物資料結構

### `FictionalEvent`

- `id`：穩定的虛構事件識別碼。
- `archetype`：抽象事件類型，例如施政爭議、資訊查核、地方服務、跨境風險、災害應變、組織分歧或投票動員。
- `trigger`：週次／遊戲狀態條件、前置旗標、角色關係或玩家先前選擇；不使用真實事件日期作周年重演。
- `scene`：虛構地點、虛構組織、虛構人物和可公開查證的本局材料。
- `choices`：不同且可承擔代價的解法，可略過、延後或轉交；選擇會留下後續旗標。
- `effects`：只更新遊戲狀態，例如議題熱度、團隊信任、組織、預算、體力、施政／議題評價及支持度；不直接掛接來源人物或真實選舉結果。
- `followups`：依玩家選擇產生後續場景、角色回訪、公開紀錄或延遲代價。

### `FictionalCharacter`

- `id`、虛構姓名／稱號、職務、價值優先順序、關係及可公開資訊。
- `memory_flags` 記錄玩家已做承諾、未回覆陳情、曾更正的說法、協作界線及公開紀錄。
- `voice_profile` 限定語氣與敘事觀點，不仿寫特定政治人物、記者或活動者的口吻。
- 避免以年齡、族群、宗教或居住地直接指定政治立場；選擇效果來自事件、政策內容和角色關係。

## 從參考素材到遊戲卡片的流程

1. **抽象化：**只記錄需要被模擬的遊戲問題，例如「一方組織擴張後，另一方可能反動員」或「簽名數與有效名冊不是同一個指標」。
2. **合成：**把不同年代、不同層級、不同背景的多個觀察合成一個虛構事件；不保留可辨識的獨特口號、專有名詞、關鍵道具、精確日期、票數及司法案件組合。
3. **改寫：**另設虛構地名、組織、職務、人物關係與劇情因果，不沿用單一史實的角色分工、起因、過程、結局。
4. **遊戲化：**將選項改成可比較的策略取捨，呈現短期／延遲／反作用及反方回應；不把歷史事件當作自動加分牌。
5. **辨識性審閱：**以熟悉臺灣近代政治的人進行「是否能辨認唯一原型」檢查。可辨識時再合成、改寫或不採用；不得只換人名卻保留事件指紋。
6. **遊戲介面檢查：**確認互動畫面、`--history`、候選人／角色名稱、日誌、TSV、錯誤訊息、CLI help、文件導覽及發行素材均未洩漏真實人物／事件內容。

## P3 優先路線

### P3a：虛構化與資料隔離（已完成）

- 建立程式資料與文件參考層的邊界：`game_content.rs` 只放虛構候選人、政黨、地方聯盟、事件與場景；真實背景材料不由遊戲執行檔載入。
- 已將總統選舉候選人姓名、政黨／團體名稱、事件卡、地方盤面、日期錨點及 `--scenarios`（相容別名 `--history`）輸出改為虛構情境；不以實際姓名加「情境代表」作為匿名化。
- 罷免案例的設計啟發改成低投票參與、集中支持、高強度雙方動員等虛構盤型；電腦畫面不出現真實案例名稱、選區數字或逐案回放。
- 已在 CI 建置玩家輸出內容檢查，涵蓋情境目錄、地方／政黨清單、一般選戰與罷免輸出；檢查不使用或渲染來源案例清單。
- 已將真實縣市與精確票數從可玩介面改成虛構地方及合成票數；罷免門檻等制度規則與虛構人物故事分層呈現。
- 玩家只會在虛構世界中選擇陣營／候選人；公開選單、日誌、TSV、help、情境目錄及初始盤使用同一套虛構詞彙。

### P3b：事件鏈與角色記憶（候選人模式第一版已實作）

- 已將兩條三節點候選人故事線連成跨週事件鏈；選擇狀態會記錄里民、競選團隊及記者的遊戲內信任，以及陳情／查證線的待回應、追蹤中、已收束或暫緩狀態。
- 已加入第 6／8／10／12 週的延遲角色回訪，角色會重新提起玩家承諾、已公開資訊或未處理問題；角色信任也能影響收尾小幅支持／信任效果。
- 後續補充角色長期利益、承諾期限、履約／逾期／修復選項與可互相交錯的事件鏈，並將事件包分別接入幕僚、地方與罷免模式；不可只換名字後重播同一條故事。
- 每週仍限制出現的故事抉擇數，讓劇情張力不會退化為一次灌入大量選項；各模式各自定義支持、信任、組織、議題與資源效果。
- 持續維護多路線測試，涵蓋選擇、略過、後續承諾未履行、關係修復與不同結局；角色與所有事件皆為虛構合成內容。

### P3c：內容回歸與品質門檻（自動化檢查已建立）

- CI 已掃描情境目錄、地方／政黨清單、候選人完整戰役與罷免戰役，確認輸出包含虛構標記並排除已知真實姓名、政黨、地名和事件名；內容作者新增新對照項時須同步維護掃描案例。
- Rust 測試驗證選舉票數向量、各週事件供給、地區／事件名稱唯一性、虛構政黨可用性與固定 seed 戰役重現；既有故事測試驗證分支選擇能延續到後續節點與回訪。
- 仍需擴充固定 seed 測試到更多遺漏、略過與重複事件情境；批次模式只比較遊戲參數，不將虛構事件效果敘述為實證因果。
- 每個內容包附上開發者用的抽象機制說明與測試範圍，不在遊戲內或 README 暗示角色／事件對應特定真人。
- 每次公開測試前仍安排內容審閱與玩家辨識度回饋；若玩家能辨認出唯一原型、像影射真人或只有改名，該內容不得進入 release。

## 完成定義

- 玩家可見的主線、候選人、政黨、地方團體、事件、地名、選舉盤與角色對話均為虛構；來源人物姓名、真實組織名稱、真實事件標題與實際結果不進入可玩輸出。
- 參考素材經多源抽象化，無單一人物／事件的一對一對應；虛構內容會因玩家選擇分歧，並有可追蹤的後續狀態。
- 開場與支持度面板說明人物、選區、事件、民調及結果是虛構遊戲模型；歷史資料僅為規則參考，不是假稱即時民意或真人預測。
- 文件清楚區分真實制度來源、模型參考用途與玩家可見虛構內容；不以「換名字」宣稱已完成虛構化。
