# 測試者回饋指引

請從 GitHub 專案的 Issues 建立回饋。描述問題時盡量附上：

- 作業系統、處理器架構、發行版本／tag。
- 操作情境（總統或地方、年份、角色、政黨範本、策略及 seed）。
- 若測試新版選單，請記下是否能快速找到行動、分類名稱是否直覺，以及 `r`（策略推薦）和 `b`（返回）是否清楚。
- 若切換難度、事件包或日期時序，請附上選項和值；事件日期映射只是遊戲排程，請指出你覺得節奏突兀或分類不合的事件。
- 若測試 `--staffer`，請回報六次幕僚會議的選擇是否改變後續場景／每日行動排序、每日短場景是否連貫或重複、主軸與事件提示是否有用，以及民調檢視是否容易解讀。
- 若測試地方模式，請記下四段地方故事選擇（第 3／6／9／12 週）各自的選項、人物關係回饋、預算／支持度變化，以及最後的故事結局；也可比較不同選法是否帶來可辨識的分歧。
- 請確認直接啟動執行檔時是否清楚看見三種遊戲模式，選取幕僚或罷免後是否進入對應流程；若使用命令列參數，請記下啟動方式及是否符合預期。
- 若遊戲中斷，請附上發生前的重現步驟、模式、週次與 seed；檢查執行檔旁是否有 `project-twn-crash.log`，Windows 也請檢查 `%TEMP%\project-twn-crash.log`。命令列錯誤與 Rust panic 會嘗試寫入診斷紀錄；強制關閉或未觸發 panic 的狀況可能沒有 log。分享前請先檢查紀錄中的路徑或自訂資料。互動遊戲可先用 `--save` 保留進度；EOF 或確認離開時會保留可續玩的存檔。
- 若使用雙擊啟動，請回報主控台是否在結束／錯誤後等待 Enter；也可在命令提示字元或 PowerShell 執行，並附上 `--version` 顯示的版本與 commit。
- 若測試存檔續玩，請記下遊戲版本、存檔版本、地方／全國模式及載入後接續的週次；版本 1 存檔應可讀取，新的地方故事決策會以版本 2 格式記錄。
- 重現步驟、預期結果、實際結果；若有錯誤訊息請貼文字。
- 你是否完成一場、遊玩時間、最有趣與最疲乏的部分。
- 對操作可理解性、策略差異、歷史呈現與重玩的簡短評分（可留空）。

不要在回報中放入個人敏感資料。批次 TSV 可能包含你設定的情境選項，分享前先檢查內容。沒有足夠的測試樣本時，單一回饋只作為待查案例，不代表整體玩家評價。
