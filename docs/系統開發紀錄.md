## 核心架構決策

1. **資料與規則分離：**選舉結果及事件卡放在 `history.rs`；行動和狀態轉移在 `sim.rs`；命令列只呼叫引擎。
2. **無外部 runtime 依賴：**保留 Rust 2021 與零第三方 crate，降低建置負擔，確保 deterministic 測試容易重現。
3. **回傳型錯誤：**引擎採 `Result<ActionOutcome, GameError>`，讓呼叫端可測試錯誤類型，而非比對錯誤字串。
4. **一致狀態與結算：**民調以百分比向量維持總和；分眾加權結果同步成總體；`finish()` 結果快取並鎖定行動。
5. **歷史保守表述：**不把人物爭議、司法起訴或個別抗爭機械轉成黨派優劣或真實選舉因果。

## 開發流程

每次改動需：

1. 修改程式與相應說明，檢查歷史卡片的來源及法律狀態措辭。
2. `cargo fmt --check`、`cargo check --all-targets`、`cargo clippy --all-targets -- -D warnings`、`cargo test`。
3. 如果環境缺少原生 linker，記錄 `cargo test` 真正阻斷點；有需要時在有 Rust MSVC 工具鏈的 CI 上完成連結與測試。
4. 對改動內容抽樣執行 CLI（`--history`、`--regions`、自動模式）並檢查輸出是否仍標示為情境模型。
5. 更新本紀錄的狀態，不將未執行項目記成通過。
