# 遊戲架構與核心引擎

## 目的與範圍

Project-TWN 是可重現的選戰策略沙盒，不是民調預測器。它把虛構的年度選戰盤、公共議題事件、玩家每日行動與分眾支持度放進 Rust 核心。玩家可以扮演執政／連任方或在野挑戰方；地方模式以 22 個虛構地區及其情境聯盟為背景，另提供黨內初選流程。

## 模組責任

| 模組 | 職責 |
| --- | --- |
| `src/game_content.rs` | 保存玩家可見的虛構年度選戰、候選人、政黨／聯盟、地方、事件卡、選民原型與合成支持設定；執行檔不載入真實人物、政黨、地名、事件或結果表。 |
| `src/campaign.rs` | 單場難度、事件包篩選、固定 seed 週次及虛構日期錨點排程；錨點只映射本作事件卡。 |
| `src/sim.rs` | 回合時鐘、陣營與共通選戰行動、預算／體力／信任／動員、候選人支持度、獨立施政評價／議題評價、分眾、組織量能、誠信揭露及懲處、協調、故事進度、固定種子亂數、結算與狀態驗證。 |
| `src/governance.rs` | 與候選人支持度分離的遊戲內施政滿意度、議題評價及議題關注度指標；不代表真實民調或人口抽樣。 |
| `src/recall.rs` | 獨立人民罷免規則、分階段時鐘、提議／有效連署／雙方動員、行動限制、違規名冊查核懲處及結算。人物、選區與盤型均為虛構。 |
| `src/electoral.rs` | 從候選人盤面及團隊狀態估算政黨票情境，依門檻與席次總額分配不分區政黨席次。 |
| `src/election_night.rs` | 將終局候選人支持度分配至 22 個虛構地區，逐區結算後與全國總票數精確核對。 |
| `src/roster.rs` | 版本化 TSV 候選人名冊的讀寫、驗證與互動編輯器。 |
| `src/savegame.rs` | 版本化、固定 seed 的互動戰役決策日誌、載入重播與狀態驗證。 |
| `src/story.rs` | 多週故事節點、分歧場景、選項成本／效果、連貫路線加成與故事進度摘要；情境內容採虛構合成角色，不宣稱是真實事件紀錄。 |
| `src/staffer.rs` | 幕僚模式的六次策略會議、12 週每日短場景、人物回訪、路線紀錄與主軸連貫加成；故事均為虛構合成情境。 |
| `src/strategy.rs` | 可組合八軸策略模組、七種策略權重、狀態式行動排序；幕僚模式會依玩家選定主軸加入每日行動排序偏好。 |
| `src/primary.rs` | 四回合虛構黨內提名；三位候選人的基礎民調、政策／組織／溝通行動、對比／互比情境及協商。 |
| `src/main.rs` | 命令列參數、分層行動選單、故事情境選擇、虛構情境／政黨／地方清單、結果與戰績 TSV 輸出。選單分類是純呈現層；合法性與行動規則仍由核心引擎判定。 |
| `src/lib.rs` | 對外匯出可供測試及未來介面使用的遊戲模組，包含選舉開票、席次換算、名冊、存檔與各模式引擎。 |

## 主要資料流

```text
命令列情境／年份／角色／種子／難度／事件包／時序
        ↓
`game_content.rs` 以虛構年度／地方情境建立一般選舉 GameState
        ↓
篩選所選事件內容，依固定 seed 或虛構日期錨點排入 12 週；另排陣營任務
        ↓
策略引擎：預覽各合法行動 → 模組分項評分 → 依策略權重排序
        ↓
每一天：驗證行動 → 支付資源 → 變更分眾支持 → 協調／查核懲處 → 對手回應 → 更新組織與任務
        ↓ 每週第 7 天
補給預算、進入下週、重置任務進度與週限定協調標記
        ↓ 一般模式：第 2／4／6／8／10／12 週故事選擇（不耗用每日回合）
處理兩條交錯的情境故事 → 記錄選擇 → 改變後續場景與少量遊戲狀態
        ↓ 幕僚模式：第 1／3／5／7／9／11 週策略會議＋84 則每日短場景
主軸、陳情、拜會、事件回應、支持度檢視、最後布局 → 影響資源、支持度與每日行動排序
        ↓ 完成 84 日或玩家提前結算
1,200 次終盤誤差抽樣 → ElectionOutcome
```

### 狀態與時鐘

`GameState` 是單場遊戲的唯一權威狀態：候選人、玩家角色與能力、總體及分眾民調、難度與事件包設定、預算、信任、動員動能、體力、總部／後援會與地面量能、負面行動揭露次數及懲處累計、週／日、事件池與事件排程、陣營任務排程與進度、一般故事與幕僚決策進度、每週一次的協調狀態，以及選舉結果快取。遊戲以 12 週 × 7 日推進，每次 `apply_action` 消耗一天；第 7 天結算後依難度補給 6–10 點預算（上限 120），再切到下週。因互動模式可提早結算，`finish()` 在任何尚未完成的日子均可呼叫。

`CampaignPhase` 只是行程標籤：第 1–4 週布局、第 5–8 週議題攻防、第 9–12 週決戰。它目前不另外乘上階段效果，玩家不應把階段名當成隱藏規則。

### 支持度、施政評價與分眾

民調向量以所有候選人合計 100% 表示。每個選民原型保存一份候選人分配；行動依原型的回應敏感度與議題契合調整個別分布，再用設定權重加權回總體支持度。增加某候選人份額時，其他候選人按現有份額比例承擔相應減少；協調則把目標候選人的部分支持直接轉給玩家。

目前六個互斥原型的權重、敏感度都是明示的遊戲參數；各原型開局複製同一份虛構情境支持度，之後才由行動逐漸分化。因此本系統尚未建立人口統計交叉表、真實選民轉移矩陣、分區投票率或校準民調。此處原型是遊戲分類，不代表人口統計、實際選民占比或已校準的轉移矩陣。

候選人支持度、政府施政滿意度、政策議題評價、議題關注度和競選團隊信任是五種不同遊戲指標，不作一比一換算。`governance.rs` 保存施政評價與議題指標；完整檢視以「關注度 × 評價落差」列出待處理優先序，策略引擎會稍微提高符合高壓議題的行動排序。在野監督、執政政策回應、服務表現及危機處置可影響相應評價，但不保證轉成候選人票數。所有面板均是合成情境狀態，不是實際國政民調。

P3a 已完成執行資料隔離：玩家可見候選人、政黨、團體、地區、事件、票數與結果皆為虛構設定。`--scenarios` 及相容別名 `--history` 都只顯示虛構情境；開發參考資料放在文件層，不被 Rust 遊戲模組載入。

### 行動、事件與協調

互動行動先依政策治理、地面組織、社區關懷、公共溝通、協調整合、高風險攻防及整備休息分組，再在分類內依策略分數排序。`r` 可直接執行策略引擎首選，`b` 返回分類、`p` 開啟即時支持度檢視、`?` 顯示操作說明；分類內可輸入 `d 編號` 閱讀行動描述、模型效果、風險與推薦理由，再以編號執行或 `r` 執行該類首選。`q` 會先確認再提前結算。分類只縮小同時顯示的資訊量，不改變行動集合、費用或平衡規則；單元測試保證全部 `ActionId` 恰好落入一類。

行動規格統一列出費用、基礎支持變化、信任與動員變化、關聯議題、體力成本／恢復。正面行動涵蓋總部及後援會、地面拜票與動員、社區服務和勘災；中立行動涵蓋辯論、媒體溝通、政見與宗教／社區公開活動；負面高風險行動為抽象的假民調、匿名黑函及輿論操作。宗教參與不預設群體政治傾向，也不設定固定轉票。玩家每日選一項陣營可用行動；費用不足、角色不適用、單次組織重複、週限定協商重複、候選人數不足或競選已結束時，核心回傳 `GameError`，不以字串分支散落在使用介面。

`GameState::preview_action()` 使用與實際行動共用的支持更新規則，不消耗 RNG 或修改狀態；預覽含直接支持變化、協調成功率×平均轉移率、對手平均回應、信任／動員／體力、任務契合、組織增量及負面操作揭露機率／期望懲處資源。總部與後援會各可成立一次，累積地面調度量能並提高後續地面行動效果。負面操作遭查核時會降低支持、信任與動員並扣除遊戲資源，重複執行及既有揭露會提高風險；預覽顯示機率加權期望，實際執行才使用固定 seed 抽取揭露結果。隨機波動以期望值 0 處理、對手回應以目前模型區間中點估計，因此是一步模型期望，不是精確未來結果。實際執行後另顯示目前支持度前後差、風險結果與組織量能。

首次啟動會提供快速開始提示，說明每日決策、行動捷徑與資源規劃。每日即時狀態以文字明確區分「候選人支持度（對比式）」與全國「政黨票支持度（不分區情境）」；地方候選人選舉不另設政黨票支持度。候選人與玩家政黨以 `▶` 識別，策略引擎首選以 `★ 推薦` 標示，執行後以 `✓【已選】` 回報。每週結束自動顯示戰情回顧，列出各候選人支持變化、目前領先／落後、團隊信任與施政滿意度變化、支持分眾變動較大的原型，以及週任務是否完成。玩家輸入 `p` 可展開候選人、政黨票、分眾權重與互比試算，採漸進揭露避免開場資訊過載。這些狀態與週報均由固定 seed 的遊戲模型產生，不是實際民調或選舉預測；地方模式也不會把候選人得票誤標成政黨票。

`StrategyEngine` 由 `StrategyModule` 組成：支持度、事件／地方脈絡、信任、投票動員、每週任務、資源續航、誠信風險及組織基礎。策略檔案 `--strategy` 選擇七組權重（含低風險權重的 `hardball`）；互動模式呈現所有合法行動的排序、分類及風險理由，`--auto` 選第一名。引擎的策略分數是排序啟發式，並非行動收益的機率估計或真實政治策略建議。`--sweep-strategies` 以相同 seed 比較七種固定權重組合，最多 1,000 個 seed；比較結果是特定示範決策流程下的模型行為。

事件卡以議題標籤連結當週策略，行動涵蓋事件議題時給予小幅模擬加成並記錄回應。預設週次由事件包以 seed 排程；`--timeline date` 會將虛構事件卡的遊戲日期錨點映射到戰役日曆；未排到事件的週次保留空白，不表示歷史重演。未來事件卡只保留抽象機制，故事日期、地點、機構、角色、因果與後果均重新創作。

### 人民罷免獨立模式

`--recall` 使用 `RecallState`，不與總統／地方選戰的候選人支持度共用勝負演算法。流程分為提議、連署及投票宣傳；門檻按虛構選舉人數以 1% 提議、10% 有效連署、同意票至少 1/4 且多於不同意票計算。開場檢查虛構目標是否為就職滿一年的區域立委；提議與連署各有行政查對狀態，接近門檻但不足時最多提供一次、10 日補提。雙方各有行動與資源，違規名冊不計入有效人數；結果顯示未達標的具體原因。每個策略區塊回報玩家及對手行動後的進度、支持意向、估計票數與目標服務紀錄變化。罷免通過只表示職位將出缺；本模式不直接指派席次，也不預設補選結果。

不實連署與死亡連署只作違規高風險遊戲選項：增加的表面數量不會被計入有效連署，並帶來查核、信任及資源懲處風險；不提供任何現實名冊操作流程。假資料未遭查核也不會改變有效門檻或最終票數。

三候選人以上可採「對比／互比民調與整合協商」行動，對手最弱候選人的支持有機率部分轉移；跨黨協商依政黨多軸情境接近度及信任估算成功率，成功後亦只轉移一部分。這些是遊戲試算規則，不等於現實支持者一定轉移、候選人必然結盟或特定民調模型。

每週任務按陣營從 4 種策略目標中 seed 洗牌，完成 2 次相符行動即可領取最多 1 點預算獎勵；每週只計一次，當預算已達上限時不累積溢出。任務讓玩家考慮一週內的行動組合與資源規劃，不直接給民調加成，也不做任務失敗懲罰。策略引擎將任務契合納入分數，實際是否優先任務取決於權重組合及其他局勢因素。

### 多週故事情境

`story.rs` 提供兩條交錯的三段式支線，共六個節點，分別落在第 2／6／10 週與第 4／8／12 週。第一條處理豪雨積水與公車改道陳情；第二條以剪輯片段的來源查證、公開回應與選戰收尾為題。各節點依先前選擇切換場景，每段提供三種解法或略過；選擇改變支持、信任、動員、體力與預算，不消耗 84 次每日行動。角色記憶持續記錄里民、團隊及記者信任與事件線狀態；延遲回訪會提醒玩家前次承諾或未回覆事項，累積關係也能帶來小幅收尾效果。自動模式也會顯示劇情場景並按固定評分挑選可負擔的解法；單場與批次 TSV 保存六節點 `story_path` 供重現分析。

候選人模式會呈現完整 12 週／84 日的每日選戰場景，並在每日行動後依行動類型、競選階段、協調結果或查核結果提供候選人視角的劇情後續。六個多週故事節點穿插在每日場景中；玩家可以從六次路線回聲和雙線結局回顧看見選擇如何延續。畫面另列遊戲模型中的對手支持度變化，這不是實際民調。所有人物與對話均為虛構合成素材，不把單一史實事件硬套成固定黨派效果。

### 幕僚模式垂直切片

`--staffer` 將玩家定位為候選人競選團隊幕僚；候選人、年份、地區及陣營仍由既有戰役設定決定。12 週內安排六次會議，分別處理競選主軸、陳情、地方拜會、事件應變、支持度檢視及最後布局。每次三個方案都呈現預算、支持度、團隊信任、動員及體力取捨；可略過，不消耗每日行動。主軸選擇會用策略模組改變後續每日行動排序，呼應當週事件或延續主軸則給予小幅情境加成，連貫選擇可在結尾獲得有限回饋。

幕僚模式沿用 84 段每日短場景，依 12 週主線逐步推進：從定調、陳情、地方網絡、攻防與支持度檢視，走向團隊分歧、最後協調及投票日前夕。每段用人物需求、資訊落差或資源衝突建立當日張力；行動結果會顯示對手模型回應，並依幕僚視角補上後續。選擇會改變後續會議場景／每日策略偏好，並以 `staffer_path` 記入單場 TSV。情境角色與對話皆是虛構合成素材，不代表歷史人物或特定真實陣營的發言。

`--save`／`--load` 支援候選人、幕僚與罷免互動戰役續玩；存檔記錄版本、初始設定、seed、自訂名冊及逐步操作，讀檔重建並重播日誌，不儲存易與引擎版本脫鉤的裸狀態快照。自動示範及批次模式不支援此功能。幕僚職涯、多人分工及獨立批次幕僚策略比較仍未實作；`--staffer` 不與 `--primary` 或 `--batch` 並用。自動示範以固定評分處理幕僚會議，提供可重現對照，不等同最佳玩家路線。

### 候選人名冊與投票日結果

`--roster-editor 路徑.tsv` 建立或編輯 2–5 位候選人的虛構名冊；每列包含姓名、內建虛構政黨、起始支持度與玩家席位。`--roster 路徑.tsv` 將名冊套用至總統或地方單場；名冊格式有版本標頭，會驗證欄位、姓名、政黨、支持值與玩家席位，並可放入戰役存檔。名冊不會改寫內建情境。

總統情境結算時，固定 seed 會把全國終局候選人票分配至 22 個虛構地區，逐區揭露投票率、領先者及累計票數；所有地區候選人票合計與全國終局票數精確一致。地方模式只結算所選虛構地區。另將政黨支持情境與候選人支持度分開計算，以政黨票估算套用 5% 門檻及 34 席總額分配不分區政黨席次；此切片只算政黨席次總額，不建構個別不分區名單當選人。這些均為遊戲生成結果，不是實際開票預測。

### 隨機性、結算與重現

`sim.rs` 內部的輕量線性同餘亂數產生器由使用者 seed 初始化，事件排程、每日微幅波動、對手回應、協調結果與結算共用同一個狀態。相同情境、相同 seed、相同行動順序可重現同一場。`finish()` 以 1,200 次、玩家支持度 ±4 點的終盤誤差抽樣估算玩家勝率；動員動能另外以有上限的小幅調整影響抽樣。結果是模型情境，不是實際開票預測；此抽樣尚未以真實選舉校準。

結算結果會快取，重複呼叫 `finish()` 不會重新抽樣；已結算狀態不接受新行動。`validate()` 用於測試時檢查候選人與民調尺寸、百分比總和、分眾權重及加權總體一致、資源與時鐘界線、事件排程及選舉結果結構。

## 狀態轉移公式（概念層）

```text
action_swing = base × action_scale + matching_event × event_scale
             + matching_local_focus × local_scale + trust_modifier × trust_scale
             + skill_modifier + fatigue_modifier × fatigue_scale + seeded_jitter × daily_noise_scale
candidate_share += clamp(action_swing)
segment_share_delta ∝ issue_match × responsiveness
aggregate_polls = Σ(segment_polls × segment_weight)
terminal_noise = seeded_uniform(-4, 4) × terminal_noise_scale
```

`ModelParameters` 目前開放上述 7 個倍率，預設皆為 1.0；`--sensitivity` 以固定 seed 配對測試每一倍率的 0.8× 與 1.2×，一次只改一項。`--interaction-sensitivity` 對 21 組參數配對分別執行四個 0.8×／1.2× 角點，計算終局支持與模型內勝率的差中差 ΔΔ；每 seed 84 場，最多 100 個 seed。批次 TSV 保留兩個參數名稱與倍率，方便逐角點重算。這檢查規則是否有非加成反應，不代表真實因果、參數估計或選舉校準。實際係數、界限、資源成本以 `ActionSpec` 及 `GameState::apply_action` 的實作為準。修改平衡參數時需更新測試與[策略系統](策略系統.md)，不把公式簡化版當作完全相等的統計估計。

## 已知邊界與後續擴充

- P2a–P2j 核心切片均已實作：含存檔／讀檔、名冊編輯器、政黨票席次換算與虛構地區逐區開票；真人試玩和可讀性驗證仍待進行。
- 尚無跨場賽季／職涯、人類玩家對戰、幕僚多人分工或獨立批次幕僚策略比較。
- 2026 全國情境以 2024 年虛構選戰盤作遊戲基準；地方情境的起始票面也是規則設定，不是地方民調。
- P3a 已將玩家可見內容與開發參考文件分離；P3c 加入固定 seed、名稱唯一性及 CLI 輸出內容回歸檢查。
- 施政滿意度與議題評價已建立可排序的遊戲內獨立指標；尚無跨場累積、可選政務議題、調查抽樣誤差或與候選人支持度的深層政策轉換模型。
- 罷免模式已支援虛構區域立委資格檢查、提議／連署查對與各一次補提、存檔續玩；地方首長／議員目標及補選後續篇章不在目前 P2 切片範圍，罷免成功不會預先指定補選勝方。
- 現有 `--batch`／`--sweep-styles`／`--sweep-strategies`／`--sensitivity`／`--interaction-sensitivity` 可檢視策略與能力風格、7 個模型倍率及其二因子交互作用；倍率範圍是工程測試值，不是估計誤差或真實選舉回測。
- 後續非玩家測試工作聚焦：延伸幕僚／地方／罷免的角色記憶與分歧故事、跨場戰役結構，以及未來圖形介面；遊戲品質雷達與平衡判斷仍需真人試玩資料。
- P3b 第一版只覆蓋一般候選人雙線故事；擴充時讓幕僚、地方及罷免模式各有事件包、角色記憶與跨週回訪，避免不同模式共用同一套結果係數。虛構內容規範見[虛構人物與事件設計規範](虛構內容設計規範.md)。
