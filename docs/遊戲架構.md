# 遊戲架構與核心引擎

## 目的與範圍

Project-TWN 是可重現的選戰策略沙盒，不是民調預測器。它把歷屆選舉結果、公共事件、玩家每日行動與分眾支持度放進一個簡單、可測試的 Rust 核心。玩家可以扮演執政／連任方或在野挑戰方；地方模式以 2022 縣市長政黨版圖作背景，另提供黨內初選流程。

## 模組責任

| 模組 | 職責 |
| --- | --- |
| `src/history.rs` | 總統選舉候選人與票數、地方及政黨情境、事件卡、選民原型設定、歷史資料查詢。來源與資料限制記錄在[歷史與來源](歷史與來源.md)。 |
| `src/sim.rs` | 回合時鐘、陣營可用行動、預算／體力／信任／動員、分眾民調、事件與地方議題加成、協調、固定種子的隨機數、結算與狀態驗證。 |
| `src/primary.rs` | 四回合虛構黨內提名；三位候選人的基礎民調、政策／組織／溝通行動、對比／互比情境及協商。 |
| `src/main.rs` | 命令列參數、互動操作、歷史／政黨／地方清單、結果與戰績 TSV 輸出。此處不應持有另一份競選規則。 |
| `src/lib.rs` | 對外匯出可供測試及未來介面使用的 `history`、`primary`、`sim` 模組。 |

## 主要資料流

```text
命令列情境／年份／角色／種子
        ↓
歷史選舉或地方情境建立 GameState
        ↓
選出 12 週事件焦點及陣營任務（固定 seed）
        ↓
每一天：驗證行動 → 支付資源 → 變更分眾支持 → 對手回應 → 更新任務進度
        ↓ 每週第 7 天
補給預算、進入下週、重置任務進度與週限定協調標記
        ↓ 完成 84 日或玩家提前結算
1,200 次終盤誤差抽樣 → ElectionOutcome
```

### 狀態與時鐘

`GameState` 是單場遊戲的唯一權威狀態：候選人、玩家角色與能力、總體及分眾民調、預算、信任、動員動能、體力、週／日、事件池與事件排程、陣營任務排程與進度、每週一次的協調狀態，以及選舉結果快取。遊戲以 12 週 × 7 日推進，每次 `apply_action` 消耗一天；第 7 天結算後先補給最多 8 點預算（上限 120），再切到下週。因互動模式可提早結算，`finish()` 在任何尚未完成的日子均可呼叫。

`CampaignPhase` 只是行程標籤：第 1–4 週布局、第 5–8 週議題攻防、第 9–12 週決戰。它目前不另外乘上階段效果，玩家不應把階段名當成隱藏規則。

### 民調與分眾

民調向量以所有候選人合計 100% 表示。每個選民原型保存一份候選人分配；行動依原型的回應敏感度與議題契合調整個別分布，再用設定權重加權回總體支持度。增加某候選人份額時，其他候選人按現有份額比例承擔相應減少；協調則把目標候選人的部分支持直接轉給玩家。

目前六個互斥原型的權重、敏感度都是明示的遊戲參數；各原型開局複製同一份歷史／情境民調，之後才由行動逐漸分化。因此本系統尚未建立人口統計交叉表、真實選民轉移矩陣、分區投票率或校準民調。詳見[選民結構分析與限制](歷史與來源.md#選民結構研究資料與遊戲原型)。

### 行動、事件與協調

行動規格統一列出費用、基礎支持變化、信任與動員變化、關聯議題、體力成本／恢復。玩家每日選一項陣營可用行動；費用不足、角色不適用、週限定協商重複、候選人數不足或競選已結束時，核心回傳 `GameError`，不以字串分支散落在 UI。

事件卡只有議題標籤，作用是：當週若行動涵蓋事件議題，給予小幅模擬加成並記錄回應。它不含固定政黨好壞方向，也不模擬新聞擴散的精確日期或個別選民心理。每週焦點由可抽事件池以 seed 洗牌排程，事件少於 12 張時重洗循環；歷史年表列出的事件不保證每場都抽到。

三候選人以上可採「對比／互比民調與整合協商」行動，對手最弱候選人的支持有機率部分轉移；跨黨協商依政黨多軸情境接近度及信任估算成功率，成功後亦只轉移一部分。這些是遊戲試算規則，不等於現實支持者一定轉移、候選人必然結盟或特定民調模型。

每週任務按陣營從 4 種策略目標中 seed 洗牌，完成 2 次相符行動即可領取最多 1 點預算獎勵；每週只計一次，當預算已達上限時不累積溢出。任務讓玩家考慮一週內的行動組合與資源規劃，不直接給民調加成，也不做任務失敗懲罰。自動示範會優先選擇有助當週任務的可用行動。

### 隨機性、結算與重現

`sim.rs` 內部的輕量線性同餘亂數產生器由使用者 seed 初始化，事件排程、每日微幅波動、對手回應、協調結果與結算共用同一個狀態。相同情境、相同 seed、相同行動順序可重現同一場。`finish()` 以 1,200 次、玩家支持度 ±4 點的終盤誤差抽樣估算玩家勝率；動員動能另外以有上限的小幅調整影響抽樣。結果是模型情境，不是實際開票預測；此抽樣尚未以真實選舉校準。

結算結果會快取，重複呼叫 `finish()` 不會重新抽樣；已結算狀態不接受新行動。`validate()` 用於測試時檢查候選人與民調尺寸、百分比總和、分眾權重及加權總體一致、資源與時鐘界線、事件排程及選舉結果結構。

## 狀態轉移公式（概念層）

```text
action_swing = base + matching_event + matching_local_focus
             + trust_modifier + skill_modifier + fatigue_modifier + seeded_jitter
candidate_share += clamp(action_swing)
segment_share_delta ∝ issue_match × responsiveness
aggregate_polls = Σ(segment_polls × segment_weight)
```

實際係數、界限、資源成本以 `ActionSpec` 及 `GameState::apply_action` 的實作為準。修改平衡參數時需更新測試與[策略系統](策略系統.md)，不把公式簡化版當作完全相等的統計估計。

## 已知邊界與後續擴充

- 目前沒有存檔／讀檔，也沒有跨場賽季、候選人名冊編輯器、逐縣市開票／席次轉換及人類玩家對戰。
- 2026 全國情境以最近一次總統選舉為全國代理；地方情境的起始票面是規則設定，不是地方民調。
- 暫無事件發生日期至競選週的時間映射；歷史事件主要提供議題情境，避免將其影響固定化。
- 現有 `--batch`／`--sweep-styles` 可比較固定示範策略和能力風格，但尚未公開掃描引擎係數，亦未構成真實選舉回測。
- 建議按優先度逐步加入：存檔格式版本化、可設定事件日期／可選事件包、更多地方選舉實際得票資料、模型係數敏感度與校準流程、玩家測試紀錄。
